Dictation
Recording / supplied static screenshot		 Showing that speech-to-text capture is active while the user dictates a message. Microphone capture is inactive, permission is pending, or speech resources are still preparing. Distinguish preparing from recording. Reserve capture feedback for actual microphone capture. Validate any audio-reactive motion against real input; retain a clear recording state and stop action with Reduced Motion.
Voice mode
Listening / speaking shared visual reference
Supplied static screenshot 		Communicating listening and spoken output during a voice conversation. Connecting, muted, idle, or disconnected; do not imply that audio is being captured or played when it is not. Separate connecting, listening, and speaking. Validate signal-driven feedback with live audio, not a decorative loading loop. Preserve explicit states with Reduced Motion; stop audio visualization when inactive to avoid unnecessary CPU work.
Image-generation loading / reveal
Generation frame / reveal not shown		 Communicating image generation and bridging the wait to the generated result. Unrelated loading or visual decoration without a connection to the output. Feature-specific loading with an expressive layer. Keep outside the purely decorative bucket; validate its added value and CPU cost.

Performance: PixelSpinner cost more CPU in our browser prototype, especially with many instances. Native cost is unverified; the one-primary rule is a design constraint, not a measured CPU threshold.

Lifecycle and accessibility: Stop when work ends; pause when hidden or offscreen. Reduced Motion must retain understandable status without continuous animation.

Timing: Retain current 1,820 ms PixelSpinner and 1,500 ms rotating-spinner baselines for now. Shared 1,500 ms timing remains an experiment, not an adopted rule.

Scope: Bars and countdowns are included as related motion patterns, not small animated icons. Dictation and voice mode use supplied screenshots. Hypothetical spinner-in-button placements remain excluded.

Confetti
Single captured celebration burst		 Brief celebration of a meaningful, confirmed achievement. Routine success, frequent actions, ongoing work, errors, or repeating celebration. Keep sparingly; play once. Never make it the only confirmation of success. Omit the burst with Reduced Motion.
Animated pet
Optional character / static fixture frame		 Optional personality and personalization. Communicating operational status or competing with focused work. Separate from loading. Keep optional and easy to disable; pause offscreen and respect Reduced Motion.

Performance: Bound particle counts and duration; avoid perpetual decorative updates when the user cannot see them.

Keep or consolidate: A one-off is not automatically wasteful. Keep it only when its distinct benefit outweighs distraction, maintenance, and runtime cost.
